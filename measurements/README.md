# 実測結果

2026-11-08、固定したMSVC release実行ファイルで測った**アイドル時の予備値**です。描画量の同等性・日本語IME・クリップボードは未確認で、採用エンジンを決めるための比較は完了していません。

| Servo 0.7.0 | 261.434 | 111.691 | 0.000 | 123.387 | 15.680 | 1 |

| WebView2 / wry 0.57.1 | 144.496 | 295.695 | 0.151 | 24.738 | 1.840 | 7 |

各構成3回。メモリとGPUは各回のサンプル中央値を求め、その3値の中央値を表示しています。CPUは各回の有効サンプル平均の中央値です。CPUの各回平均はServoが0.000〜0.051%、Blitzが0.000%、WebView2が0.104〜0.548%でした。0.000%は採取したCPU時間の増分が検出されなかったという意味です。

Private Bytesはプライベートコミットで、物理RAMの使用量ではありません。Working Set合計には共有ページの重複があります。特に複数プロセスのWebView2を、システム全体のRAM増分として解釈しないでください。GPUメモリもCPUメモリへ加算しません。

この条件では、BlitzのPrivate Bytes・Working Set・GPUメモリはいずれもServoより多い値でした。ただし、両者が同じ画面を正しく描画していることを目視検証できていないため、軽量性や採用の最終結論にはしません。

## 測定条件

- Windows 10 Home 10.0.19045、Intel Core i7-4790（4コア/8スレッド）、物理メモリ17,119,154,176 bytes。
- NVIDIA GeForce GTX 1070 Ti、ドライバー32.0.15.6094。ディスプレイ2560×1440。DPI倍率と電源プランは未記録で、既存設定を変更していません。
- Rust/Cargo 1.99.1、`stable-x86_64-pc-windows-msvc`、`--release --locked -j2`。Servo 0.7.0には記録済みの公式OpenGL初期化修正を適用。
- 3本ともソースコミット`80b45e15cbbf583cc57390f8855e1d297744481f`からビルドした実行ファイル。比較中は再ビルドせず、[バイナリーのSHA-256](2026-11-08/binaries.json)が前後で一致することを確認。現在の`probes/`と`ui/`もこのコミットと同一です。
- [UIとCargo.lockのSHA-256](2026-11-08/inputs.json)を保存。改行を含むWindows作業ツリーの実バイト列のハッシュです。UIは初期状態、100件、1000×720論理ピクセル。外観が同じであることは未確認です。
- WebView2 Runtime 157.0.4341.42。検証用プロセスの実体と専用プロファイルの`Last Version`で確認。事前にプロファイルを作成し、同じキャッシュを保持しました。
- 各候補を15秒ずつ一度起動して準備し、毎回起動後10秒待機、30秒間のアイドルを採取しました。OS再起動はしていないため、コールド起動の測定ではありません。
- 最初の測定はServo→Blitz→WebView2、Blitz→WebView2→Servo、WebView2→Servo→Blitzの順。後述のコンソール問題により、Servo/BlitzのみServo→Blitz、Blitz→Servo、Servo→Blitzの順で取り直しています。
- 取り直しでは`Start-Process -NoNewWindow`を使用し、余分なコンソールを生成しません。WebView2はGUI形式なので元の3回を使用しています。
- コンパイラー、他の候補、画面操作ヘルパーによる操作を測定中に実行していません。既存のCodex・Chrome・タスクマネージャーなどのバックグラウンドアプリは終了せず保持しました。マウス位置は制御できていません。
- 約1秒ごとにホストと子孫プロセスを採取。実際の間隔はCIM取得時間を含み、30秒あたり26〜27サンプル、経過時間30.016〜31.115秒でした。有効9回の全行でプロセス増減なし、CPU/GPU列の欠測なし。
- 終了は計測スクリプトから検証プロセスを停止しています。アプリの正常終了試験とは別です。
