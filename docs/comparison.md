# 比較手順

## まず操作が成立するか確認する

3構成で同じ確認を行い、結果を「合格 / 不合格 / 未確認」で記録します。未確認を合格として数えません。起動時のクライアント領域は1000×720論理ピクセルです。

| 確認 | 手順と合格条件 |
| --- | --- |
| ローカル画面 | ネット接続を切ってもタイトル、メモ、100件のカードが表示される |
| 日本語表示 | 文字化けや欠けがなく、改行・折り返し・選択範囲が見える |
| 入力 | マウスでtextareaを選択し、英数、改行、Backspace、Delete、矢印、Home/End、Shift選択が動く |
| IME | 「にほんご」を変換して「日本語」を確定できる。変換途中の文字が重複せず、Escで取り消せる |
| IME位置 | ウィンドウ移動・リサイズ後も、候補ウィンドウが入力位置に追従する |
| クリップボード | メモ帳と双方向に日本語・複数行・絵文字をCtrl+A/C/X/Vで交換できる |
| Rust/JSロジック | 「日本😀」で3文字、クリアで空欄・0文字になる（Unicodeスカラー値を数える） |
| スクロール | ホイールとトラックパッドで項目100まで進み、先頭へ戻れる |
| リサイズ | 横幅を640論理ピクセル以下にするとカードが1列になる。最小化から復帰できる |
| DPI | 100%/150%の画面間で移動し、描画領域とポインター位置、文字・IMEの位置が一致する |
| 終了 | 閉じる操作でホストと子プロセスが終了する |

Servoホストのキー変換はこの画面で使う文字・編集・移動・IME関連キーに限定しています。物理キーコード、ゲーム、ブラウザー操作、全キー互換性は評価対象にしていません。BlitzのイベントやCSSの未対応が見つかった場合は、見た目や入力を別実装で補わず、不合格の内容を記録します。

## 測定条件をそろえる

- 同じPC、Windows版、GPU/ドライバー、電源モード、画面、DPI、フォント、日本語IMEを使用する。
- 全て`--release --locked`で事前にビルドする。コンパイル時間を起動時間へ含めない。
- 画面は初期状態、100件、1000×720論理ピクセル。他の候補とブラウザーを終了する。
- WebView2のRuntime版を記録する。Runtimeを変えた結果は別の条件として扱う。
- 初回のWebView2プロファイル作成とシェーダー準備を一度済ませ、以後同じプロファイルとキャッシュを使う。初回起動を調べる場合は別枠で記録する。
- 各条件3回。個々の値と中央値を残す。ハードウェアとビルドのコミット、Rust版も併記する。

## 起動時間

Windowsを**再起動**し、起動後の待機時間を毎回そろえて、対象のrelease実行ファイルを直接起動します。「起動操作からメモと先頭カードが表示されるまで」を同じ方法の画面録画で測ります。60fpsなら約16.7ms単位の精度であることも記録します。

ここでのコールド起動は「OS再起動後の最初の起動」です。アプリのディスク上のキャッシュは保持します。続けて起動した値はウォーム起動として分けます。ウィンドウ作成時刻や`cargo run`の経過時間を初回描画時間の代わりにはしません。

## メモリとCPU

起動後10秒待機し、ホストのPIDをタスクマネージャーで確認します。別のPowerShellから以下を実行します。例の1234は実際のホストPIDに置き換えてください。`measure.ps1`は起動・終了・操作の自動化をしません。

```powershell
./scripts/measure.ps1 -ProcessId 1234 -Phase idle -Seconds 30 -OutputPath measurements/servo-idle-1.csv
./scripts/measure.ps1 -ProcessId 1234 -Phase scroll -Seconds 30 -OutputPath measurements/servo-scroll-1.csv
```

アイドル測定中は操作せず、カーソルをtextareaの外へ移します。スクロール測定では同じデバイス・速度で、一覧を下へ10秒、上へ10秒、下へ10秒動かします。入力操作は負荷測定と別にします。

Windowsの`Start-Process`でServo/Blitzを起動する場合は`-NoNewWindow`を付け、余分なコンソールを作らないようにします。この試作のrelease版はコンソール形式のため、新規コンソールを作ると子プロセスの`conhost.exe`も測定へ入り、今回の環境ではそのCPU負荷が結果へ混ざりました。実行ファイル自体は変更せず、ウィンドウの表示と入力はアプリ側で行います。

スクリプトは毎回ホストと子孫プロセスを列挙します。WebView2のレンダラーやGPUプロセスを除外しないためです。約1秒間隔の各サンプルをCSVへ保存します。

| 列 | 意味 |
| --- | --- |
| `PrivateMiB` | プロセス群のPrivate Bytes（プライベートコミット）の合計。物理RAM量ではない |
| `WorkingSetMiB` | プロセス群のWorking Set合計。共有ページの重複を含み、システム全体のRAM増分とは異なる |
| `CpuOneCorePercent` | サンプル間のCPU時間差÷実際の経過時間×100。100%は論理CPU1個分。タスクマネージャーの全CPU基準%とは異なる |
| `GpuDedicatedMiB` / `GpuSharedMiB` | プロセス群のGPU専用/共有メモリ合計。対応するGPUカウンターがない場合は空欄 |
| `ProcessCount` | そのサンプルで読み取ったプロセス数 |
| `ProcessSetChanged` | プロセスの増減があったか。trueの行はCPU値を空欄にする |

メモリは30秒間の中央値と最大値、CPUは有効行の平均を記録します。プロセス増減でCPUが空欄になった場合は、その回を取り直します。短時間で生成・終了した子プロセスは捉えられないため、起動時CPUの計測には使用しません。CIMによるプロセス列挙の負荷もあるので、同じスクリプト・間隔で測ります。

## GPUメモリ

`measure.ps1`はWindowsの`Win32_PerfFormattedData_GPUPerformanceCounters_GPUProcessMemory`から、ホストと子孫PIDの`DedicatedUsage`と`SharedUsage`を合算します。約1秒ごとのCSVにCPUメモリと別の列で記録し、30秒間の中央値と最大値を残します。対応するPIDのカウンターがないサンプルは空欄とし、0として扱いません。GPU/ドライバーとプロセス数を添えます。プロセスごとの合算は物理GPUメモリの正確な増分とは限りません。

## 採用の判断

日本語入力・クリップボード・必要な描画が成立した構成同士でリソースを比較します。数値差が小さい、測定が欠ける、画面の描画量が違う場合は結論を保留します。Blitzが軽いという構造上の予想を測定結果の代わりにしません。
