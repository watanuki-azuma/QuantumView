# QuantumView ロードマップ

## 目的とポジショニング

QuantumView は、Chromium や OS 標準 WebView（WebView2 等）に依存せず、HTML / CSS / JavaScript のローカル UI をデスクトップアプリへ組み込める **軽量 Rust ホスト基盤（Electron 代替）** を目指す。

* **目指すポジション**: Node.js や Chromium の全機能互換ではなく、**「OS 標準 WebView 非依存の軽量デスクトップホスト（Servo 版 Tauri）」** として実用成立させる。
* **比較基準**: Windows WebView2（`wry`）は性能・操作感・互換性の比較基準（ベンチマーク）としてのみ維持し、Chromium へのフォールバックとしては組み込まない。
* **基本方針（KISS / YAGNI）**:
  * 実装は実用最小限から切り出し、バックエンド抽象化・プラグイン機構・過剰な互換層は先に作らない。
  * 過去の試作候補（Blitz / Dioxus Native）は既存 HTML/JS の置き換え用途に合わないため除外済み（測定記録のみ保持）。

## 進める順番（5フェーズ）

### Phase 1: Servo 継続可否の先行判定（Go / No-Go ゲート）

ホイール補間パッチ（`vendor/servo-paint`）の個別調整だけで足踏みせず、採用可否の判断材料を先に揃える。

* **性能・起動計測**: 未測定の起動時間（コールド/ウォーム）とスクロール時 CPU / GPU / メモリ使用量を `scripts/measure.ps1` 等で計測し、WebView2 基準と比較する。
* **操作・入力の残課題検証**:
  * `HANDOFF.md` の残課題であるホイール1回分の実描画移動量を確認・解消する。
  * IME 候補ウィンドウの追従位置、全編集キー、トラックパッド、最小化/復元、HiDPI（拡大率変更）の挙動を確認する。
* **完了条件（ゲート）**: WebView2 と比較して、メモアプリおよび汎用 UI ホストの基盤として Servo 0.7.0 を採用継続できるかを判定する。

### Phase 2: カスタムプロトコル配信と最小 IPC の実装

`file://` 直読みによる制約（ES Modules・CORS・単一バイナリ配布の破綻）を解消し、JS ⇄ Rust の最小通信層を先に用意する。

* **カスタムスキーム配信**: ローカルの HTML / CSS / JS アセット（同梱またはバイナリ埋め込み）を独自プロトコル（例: `qv://localhost/...`）経由で配信する。
* **最小限の双方向 IPC**:
  * JS から Rust コマンドを非同期呼び出しできる `invoke`（JSON シリアライズ）と、Rust から JS へ通知するイベント仕組みを実装する。
  * ページ読み込み前に安全なブリッジ API のみを注入する初期化導線（プリロード相当）を用意する。
* **セキュリティ境界**: 外部 URL への意図しない遷移ブロックとローカル Origin 分離の最小ルールを定義する。

### Phase 3: メモアプリ v0 と最小 OS 統合の完成

Phase 2 の配信・IPC 基盤の上で、最初の実用サンプルである「メモアプリ v0」を完成させる（後工程での全面書き直しを防ぐ）。

* **メモアプリ機能**: 単一メモの編集、IPC 経由でのローカル自動保存、起動時復元、保存状態・保存失敗の UI 表示を実装する。
* **最小 OS 統合 API**:
  * ファイル選択・保存ダイアログ
  * ウィンドウサイズ/位置の保存と復元
  * クリップボード連携およびファイルドラッグ＆ドロップの最小対応
* **完了条件**: 実用サンプルとしてのメモアプリが日常利用できる品質で動作すること。

### Phase 4: 開発体験（DX）とポータブル配布の確立

アプリ開発者が UI を組んでテストし、ビルド不要で別環境へ配布できる最小ラインを整える。

* **開発時デバッグ導線**: JS コンソール出力やエラーのホスト側ログ転送、手動/簡易リロード導線など、DevTools 代替の最小デバッグ手段を整備する。
* **配布パッケージ化**: 実行ファイル（`.exe`）と UI リソースを一式化し、ソースツリー外の別フォルダ・別 PC でビルド環境なしに動作するポータブル配布形式を確立する。
* **ライセンス整理**: Servo 0.7.0 派生コード（MPL-2.0）と新規ホストコードの権利・表記を `LICENSE` / `README.md` に明記する。

### Phase 5: 汎用 WebView 代替ホスト（SDK）としての切り出し

メモアプリ固有のコードとホスト基盤を分離し、任意の HTML / CSS / JS アプリを構築できる状態にする。

* **クレート / モジュール分離**: ウィンドウ管理・Servo 統合・カスタムプロトコル・IPC・OS 統合 API を汎用ホスト層として切り出す。
* **最小テンプレート提供**: 別の最小 HTML / CSS / JS 画面と Rust コマンドを追加するだけで新規デスクトップアプリを起動できる構成を検証する。
* **Electron 代替としての拡張判断**: 必要に応じてマルチウィンドウ、システムトレイ、グローバルショートカット、自動更新を YAGNI に沿って段階追加する。

## スコープ外（当面やらないこと）

* Node.js ランタイム互換および npm ネイティブアドオンの直接実行
* Chromium への自動フォールバックやマルチエンジン切り替え機構
* プラグイン API・汎用テストフレームワークの先行構築
